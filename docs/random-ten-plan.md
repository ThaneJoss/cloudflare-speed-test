# 每轮随机十个候选：实施计划

用户授权研究、代码修改和验证；没有推送、部署、凭据、DNS 或网络安全修改授权。本轮遵循 Windows 全局 AGENTS.md：前后本地 Git 提交，中文提交信息，不记录哈希，不运行本地测试；新增测试交由已配置的 GitHub CI，但未经推送授权不启动远端执行。

1. 核实 Cloudflare 官方 IPv4/IPv6 范围，以及 XIU2/CloudflareSpeedTest 和 mydearniko/speedflare 的原始候选、实际指定 IP 的连接方法、测速所在机器和许可证。
2. 在现有网页架构中仅对真实、可验证的固定 IP HTTPS 入口池实现默认每轮随机抽取十个不同 IP；新请求重新抽样，IPv4/IPv6 规范化去重，池不足时明确说明，不伪造已配置入口。
3. 原始 CIDR/IP 只能作为候选来源，不能自动变成浏览器可测入口。记录来源与必要许可证说明；需要本地 helper、额外域名/证书/DNS 的完整路径只交付具体方案，不自动安装或改动服务。
4. 编写随机抽样、去重、每轮重新抽样、IPv4/IPv6、池不足和签名清单绑定的 CI 回归；更新页面与 README；交付改动与待批准步骤。

设计细节由原始源码研究决定。继续保留上一轮已验证的 DNS 请求修复，不使用 Worker 侧测速作为用户本地测速，不降低 TLS、CORS 或现有授权验证。

后续授权更新：用户明确批准提交和推送本轮修复与随机十候选功能。按当前检出的 main 和已有 main push CI 工作流执行，先核对远端变化，正常推送，不强推。推送可能触发已连接的 Cloudflare Builds；不额外手动部署，不等待 CI 完成，继续禁止修改凭据、安全设置或真实 DNS。

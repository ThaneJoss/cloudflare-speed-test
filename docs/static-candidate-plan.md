# 静态 CIDR 候选池实施计划

用户明确要求从 IP 网段生成候选，来源不需要实时更新。本轮授权研究、修改和候选展示，暂不推送。继续遵循 Windows 全局 AGENTS.md：实施前后本地中文提交，不记录哈希，不运行本地测试、检查或烟测；新增回归用例留待获准推送后由 GitHub CI 执行。

1. 重新读取 XIU2/CloudflareSpeedTest 的 ip.txt、ipv6.txt 并与 Cloudflare 官方文本核对。仓库当前只有空 probes.json 和来源文档，没有机器可读静态 CIDR 文件；上一轮仅从配置好的 HTTPS 探针池抽样，所以未实现原始候选来源。
2. 内置官方十五个 IPv4、七个 IPv6 网段，附来源链接与 2026-10-12 核对日期，不复制第三方源码或旧表、不增加自动更新逻辑。
3. 独立抽样模块默认每轮八个 IPv4、两个 IPv6，共十个不同 IP。每个地址族先等概率选 CIDR，再在段内均匀随机偏移；IPv4 避免该 CIDR 的网络与广播地址。IPv6 使用 BigInt 直接计算至多十六字节偏移，不枚举地址空间，重复 IP 重新抽取。
4. 增加受既有 Access/Origin 保护的候选生成接口，执行纯随机计算，不进行网络探测，不依赖 probes.json 或 DNS 凭据。候选模型明确 reachability=unknown，不带 HTTPS URL、速度或写入签名。
5. 状态和页面分开显示静态候选池与 HTTPS 探针池；即使探针为空或 DNS API 故障，候选仍可生成。真实测速和写入继续要求已配置的 HTTPS 探针及原有授权。
6. 编写静态数据、去重、默认分配、IPv6 大偏移、每轮重抽、空探针独立生成、状态/页面展示和写入拒绝的 CI 用例；交付一组由抽样函数生成的十个候选示例及真实测量限制。

生成候选示例属于用户要求的数据交付，不是网络测速或本地测试；不向这些 IP 发请求。既有探针的 DNS/官方归属验证保持原有安全边界。不得增加本机测速 helper、修改 DNS、Access、凭据或网络配置，也不得推送或部署。

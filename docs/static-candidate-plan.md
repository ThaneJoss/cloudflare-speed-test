# 静态 CIDR 候选池实施计划

用户明确要求从 IP 网段生成候选，来源不需要实时更新。最初的 Windows 实施仅获准研究、修改和展示候选，当时暂不推送，并受 Windows 全局 AGENTS.md 的本地提交和禁止本地测试约束；这些是历史执行条件。

2026-10-12 后续授权：在独立云环境中把静态候选调整为每轮十个 IPv4 加十个 IPv6，执行仓库要求的验证，并沿用既有发布分支工作流正常推送，不强推；保护规则要求 PR 时创建 draft PR。确认远端精确提交并跟进该提交的 CI 和既有自动构建结果，不额外手动部署，不修改 DNS、Access、凭据或网络配置。旧云环境补丁在本环境未取得，本次依据当前源码独立实现，不宣称读取或复用旧补丁。

1. 以已入库的官方静态 CIDR 快照和现有候选模块为基础，保持来源信息与 HTTPS 探针实测路径的区分。
2. 内置官方十五个 IPv4、七个 IPv6 网段，附来源链接与 2026-10-12 核对日期，不复制第三方源码或旧表、不增加自动更新逻辑。
3. 独立抽样模块默认每轮十个 IPv4、十个 IPv6，共二十个不同 IP。每个地址族先等概率选 CIDR，再在段内均匀随机偏移；各族分别去重，重复 IP 重新抽取，不用一个地址族补足另一个。IPv4 避免该 CIDR 的网络与广播地址。IPv6 使用 BigInt 直接计算至多十六字节偏移，不枚举地址空间。
4. 增加受既有 Access/Origin 保护的候选生成接口，执行纯随机计算，不进行网络探测，不依赖 probes.json 或 DNS 凭据。候选模型明确 reachability=unknown，不带 HTTPS URL、速度或写入签名。
5. 状态和页面分开显示静态候选池与 HTTPS 探针池；即使探针为空或 DNS API 故障，候选仍可生成。真实测速和写入继续要求已配置的 HTTPS 探针及原有授权。
6. 更新静态数据、每族去重、10+10 默认分配、IPv6 大偏移、每轮重抽、空探针独立生成、状态/页面展示和写入拒绝的回归用例，执行类型检查、单元测试、workerd DNS 回归和构建；确认静态候选仍显示未测速，真实 HTTPS 探针仍为两族合计十个。

生成候选只执行随机计算，不向这些 IP 发请求；每个候选的可达性仍未知。既有探针的 DNS/官方归属验证、授权签名和 DNS 写入安全保持原有边界；本轮不增加本机测速 helper，也不把二十个静态候选当作已验证 HTTPS 探针或真实逐 IP 测速结果。
